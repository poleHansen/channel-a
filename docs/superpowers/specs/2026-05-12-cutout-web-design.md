# 离线抠图 Web 工具设计文档

- 日期：2026-05-12
- 目标：沉淀首版离线抠图 Web 工具的产品与技术设计，作为后续实现计划与开发执行依据
- 适用范围：非商用内部工具，优先 Windows 本地运行，同时支持局域网 GPU 服务器部署

## 1. 项目目标

构建一个无需联网即可运行的抠图 Web 工具，满足以下核心要求：

1. 前端界面好看，视觉上有设计感。
2. 默认抠图效果强，适合人物和商品图。
3. 后端模型运行稳定，尽量避免环境问题。
4. 支持 GPU / CUDA 推理，并控制在 8GB 显存可运行。
5. 用户可以通过点选、框选、涂抹等方式圈出需要抠的主体。
6. 上传 RGB 图像后，既能导出 RGBA 透明图，也能导出 RGB 合成图。

## 2. 范围与非目标

### 2.1 首版范围

- 单张图精修优先，不做批量处理优先级。
- 支持自动抠图、交互修正、边缘微调、结果导出。
- 支持 Windows 本地运行与局域网访问两种部署形态。
- 支持 RGB 原图上传，导出 RGBA PNG 与 RGB PNG/JPG。

### 2.2 暂不纳入首版

- 批量上传、批量队列、批量导出。
- 多用户协作与权限系统。
- 复杂图层系统。
- 桌面壳封装（Electron/Tauri）作为首版目标。
- 商业授权与商用部署适配。

## 3. 方案概览

首版采用“双模型 + 单后端推理服务”的设计：

- 主抠图模型：`RMBG-2.0`
- 交互分割模型：`SAM 2.1`
- 前端：React 技术栈的单页精修工作台
- 后端：FastAPI 推理服务
- 运行方式：本地浏览器访问 `http://127.0.0.1:7860`，或局域网访问 `http://<server-ip>:7860`

该方案的核心思想是：

- `RMBG-2.0` 负责默认高质量背景移除，优先保证人物、商品图的初始效果。
- `SAM 2.1` 负责用户点选、框选后的交互式修正，增强任意物体场景的通用性。
- 前后端解耦，模型服务统一，避免为 Windows 本地和服务器部署维护两套逻辑。

## 4. 模型选型

### 4.1 推荐模型组合

- 自动抠图：`RMBG-2.0`
- 交互分割：`SAM 2.1`

### 4.2 选型原因

#### `RMBG-2.0`

- 更适合背景移除和 alpha matte 生成。
- 对人物、商品、主图类场景更符合“抠图工具”的目标。
- 可直接服务于 RGBA 透明图导出。
- 当前项目为非商用内部工具，许可风险可接受，但必须在文档中保留“仅限非商用内部使用”的约束。

#### `SAM 2.1`

- 适合点、框等提示驱动的交互式分割。
- 非常适合“用户自己圈出需要抠的对象”的编辑体验。
- 可作为自动结果不理想时的精修工具，而不是替代主抠图模型。

### 4.3 模型职责分工

- `RMBG-2.0`：生成首版前景 mask。
- `SAM 2.1`：根据用户正向/负向提示对局部区域重分割。
- 画笔工具：优先作为前端直接编辑 mask 的手工修正层。

### 4.4 后续可替换性

当前架构应保证模型可插拔。若未来因许可或效果需要调整，应允许：

- 用 `BiRefNet` 替换 `RMBG-2.0`
- 保持前端、数据流、导出逻辑不变

## 5. 前端设计

### 5.1 体验定位

首版定位为“高质量单图精修工作台”，不是营销展示页，也不是后台管理页。

目标是让用户上传后尽快看到结果，并能在一个统一工作区内完成查看、修正、导出。

### 5.2 页面结构

- 顶部：项目操作栏
- 左侧：素材区与版本区
- 中间：大画布预览区
- 右侧：属性、参数与导出区
- 底部或浮动工具栏：AI 抠图与修正工具

### 5.3 核心交互

#### 自动抠图

- 上传图片后自动调用 `RMBG-2.0`
- 返回首版 mask 与透明预览

#### 交互修正

支持以下修正方式：

- 点选保留区域
- 点选移除区域
- 框选主体
- 画笔涂抹保留
- 画笔擦除移除

其中：

- 点选、框选优先调用 `SAM 2.1`
- 画笔修改优先在前端直接编辑工作 mask

#### 边缘优化

首版仅提供少量高价值参数：

- 羽化
- 边缘平滑
- 发丝增强
- 去白边 / 去黑边
- 前景颜色净化

#### 导出

- `PNG RGBA`
- `PNG RGB`
- `JPG RGB`

RGB 导出需支持背景合成：

- 白底
- 黑底
- 自定义纯色

### 5.4 视觉风格

页面整体结构不变，但配色气质参考 [detail.design](https://detail.design/) 的暖米白、深灰、灰绿方向，仅借鉴色彩语言，不复刻其布局、内容或具体 UI。

建议色板：

- `--bg: #F6F1E8`
- `--panel: #FBF7F1`
- `--card: #F1E8DC`
- `--border: #D8CCBB`
- `--text: #1F1D1A`
- `--muted: #6F685F`
- `--accent: #7A8B63`
- `--accent-strong: #5F6D4D`
- `--warn: #A06D42`

视觉要求：

- 背景偏纸感暖色，不用纯白或纯黑。
- 文本使用深灰黑，不用刺眼纯黑。
- 选中态、高亮态使用克制灰绿强调色。
- 面板、卡片、画布边框轻量分层，避免后台系统风格。
- 动效只保留必要的淡入、面板过渡与结果刷新反馈。

## 6. 技术栈

### 6.1 前端

- `Vite + React`
- `Tailwind CSS`
- `shadcn/ui`
- `Framer Motion`
- `Konva`
- `Zustand`

说明：

- `Konva` 负责画布、标注点、框选、mask 覆盖层与笔刷交互。
- `Zustand` 管理轻量编辑状态、导出状态与当前任务状态。
- `Tailwind + shadcn/ui` 用于构建可维护、统一的界面系统。

### 6.2 后端

- `FastAPI`
- `Uvicorn`
- `PyTorch`
- `CUDA`
- `Pillow`
- `OpenCV`

说明：

- 后端负责模型加载、推理、mask 后处理、导出合成。
- API 与推理层拆分，便于后续替换模型实现。

## 7. 数据流与存储规则

### 7.1 输入标准化

用户上传 `jpg/jpeg/png/webp` 后，后端统一生成标准化输入：

- `source_rgb.png`

处理规则：

- 自动纠正 EXIF 方向
- 保持原始尺寸信息
- 所有主流程以 `RGB` 作为颜色输入基准

### 7.2 自动抠图流程

`RMBG-2.0` 输出：

- `auto_mask.png`：单通道灰度 mask
- `preview_rgba.png`：用于前端透明预览的 RGBA 合成结果

### 7.3 交互修正流程

系统维护一张工作 mask：

- `working_mask.png`

所有后续点选、框选、画笔、擦除、边缘处理都只修改这张 mask，不直接修改原图。

优先级规则：

1. 手工画笔修改最高
2. `SAM 2.1` 修正结果其次
3. `RMBG-2.0` 自动结果最低

### 7.4 导出规则

系统真正保存的核心不是一张“最终图”，而是：

- `RGB 原图`
- `灰度 mask`
- `导出结果`

#### RGBA 导出

- 使用 `source_rgb` 作为颜色通道
- 使用 `working_mask` 作为 alpha 通道
- 统一导出为 `PNG`

#### RGB 导出

- 将 `source_rgb` 与指定背景进行合成
- 导出 `PNG` 或 `JPG`
- 首版支持：
  - 白底
  - 黑底
  - 自定义纯色背景

### 7.5 建议文件结构

每个任务建议落盘以下文件：

- `original.xxx`
- `source_rgb.png`
- `auto_mask.png`
- `working_mask.png`
- `result_rgba.png`
- `result_rgb_white.jpg`
- `result_rgb_custom.png`
- `project.json`

`project.json` 至少记录：

- 原图尺寸
- 当前 mask 路径
- 背景设置
- 当前导出设置
- 用户编辑历史
- 是否启用边缘优化

## 8. API 设计草案

### 8.1 `POST /segment/auto`

输入：

- 原图文件

输出：

- `task_id`
- `auto_mask`
- `preview_rgba`
- 图像尺寸信息

### 8.2 `POST /segment/interactive`

输入：

- `task_id`
- 正向/负向点提示
- 框选提示

输出：

- 更新后的 `working_mask`
- 最新预览图

### 8.3 `POST /mask/brush`

输入：

- `task_id`
- 画笔轨迹
- 模式：`add` / `remove`

输出：

- 更新后的 `working_mask`

### 8.4 `POST /mask/refine`

输入：

- `task_id`
- 边缘优化参数

输出：

- 优化后的 `working_mask`
- 最新预览图

### 8.5 `POST /export`

输入：

- `task_id`
- 导出格式：`rgb` / `rgba`
- 背景参数

输出：

- 文件路径或下载流

## 9. 运行环境与部署

### 9.1 部署目标

- Windows 本地优先
- 同一套服务兼容局域网 GPU 服务器部署

### 9.2 推荐运行方式

首版采用 Web UI + 本地/局域网推理服务：

- 本地访问：`http://127.0.0.1:7860`
- 局域网访问：`http://<server-ip>:7860`

### 9.3 环境管理

推荐：

- `Python 3.10`
- `micromamba`
- 固定版本的 `PyTorch + CUDA`
- 模型权重本地化存储于 `models/`

原则：

- 避免运行时联网下载模型
- 避免用纯 `pip` 临时拼环境
- 通过 `environment.yml` 锁定版本

### 9.4 建议目录结构

```text
app/
  frontend/
  backend/
  models/
    rmbg-2.0/
    sam2.1/
  outputs/
  logs/
  scripts/
  environment.yml
  launch.ps1
  stop.ps1
```

### 9.5 启动脚本职责

`launch.ps1` 负责：

1. 检查环境是否存在
2. 检查 GPU / CUDA 是否可用
3. 检查模型文件是否齐全
4. 检查输出目录是否可写
5. 启动后端服务与前端预览服务

## 10. 8GB 显存约束策略

首版必须以“8GB 显存单图稳定可跑”为目标，不做高风险激进配置。

### 10.1 推理策略

- 默认按安全尺寸推理
- 超大图先缩放再生成 mask
- 最终将 mask 映射回原图尺寸

### 10.2 交互策略

- `SAM 2.1` 仅在用户提交点选/框选后运行
- 不在拖动或连续移动中实时全量推理

### 10.3 任务调度策略

- 首版单任务串行推理
- 不做多任务 GPU 并发
- 使用轻量任务状态机制返回 `task_id`

### 10.4 精度策略

- 优先尝试混合精度
- 若某些显卡在 Windows 上不稳定，允许回退到更保守配置

### 10.5 大图兜底策略

- 当输入超过阈值时，优先提示降尺度处理
- 二期再考虑 tile/refine

## 11. 稳定性设计

### 11.1 启动自检

启动时必须检查：

- GPU 是否可见
- CUDA 是否可用
- 模型路径是否存在
- 输出目录是否可写
- 端口是否可用

### 11.2 降级路径

- 有 GPU：走 CUDA 推理
- 无 GPU：允许进入 CPU 慢速模式或仅展示前端不可推理状态

### 11.3 日志

建议最少输出：

- `logs/backend.log`
- `logs/frontend.log`
- `logs/startup-check.log`

### 11.4 统一配置

Windows 本地与局域网服务器仅通过配置切换以下差异：

- 监听地址
- 输出目录
- 访问权限
- 日志级别

业务逻辑、模型加载、导出逻辑保持完全一致。

## 12. 测试要求

首版至少覆盖以下验证：

- 环境启动测试
- GPU 可用性测试
- 单张 RGB 上传到 RGBA 导出测试
- 单张 RGB 上传到 RGB 白底导出测试
- 点选修正测试
- 框选修正测试
- 画笔修正测试
- 超大图输入稳定性测试
- Windows 路径与中文路径测试
- 多次撤销/重做后一致性测试

重点验证场景：

- `jpg -> rgba png`
- `png(rgb) -> rgb jpg`
- `用户修正后再次导出`
- `边缘净化参数对不同背景导出的影响`

## 13. 风险与约束

### 13.1 许可风险

- `RMBG-2.0` 仅按当前确认范围用于非商用内部工具
- 若未来需要商用，必须重新评估许可与模型替代方案

### 13.2 显存风险

- 大尺寸图像在 8GB 显存环境下可能需要主动降尺度
- 首版必须优先稳定，不追求极限分辨率

### 13.3 交互复杂度风险

- 若同时实现过多高级工具，会显著拉高前端复杂度
- 首版需坚持“少而精”的编辑工具集

## 14. 开发建议

后续执行时，建议按以下顺序拆解：

1. 建立前端工作台骨架与配色系统
2. 建立 FastAPI 服务与健康检查
3. 接入 `RMBG-2.0` 自动抠图
4. 打通 RGB/RGBA 导出链路
5. 接入 `SAM 2.1` 点选/框选修正
6. 完成画笔编辑、边缘优化与任务状态管理
7. 补齐启动脚本、自检与测试
